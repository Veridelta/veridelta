# History

What changed in the product bundle and why, newest first. A commit's diff shows the change; this file keeps the reason.

## 2026-10-28

- **Update**: [the feature map](FEATURES.md) adds the page on tracing a verdict and the Action's `attest` input, and [the roadmap](../docs/roadmap.md) drops them. The page joins signed commits, code owner reviews, and the run record, and `attest` signs the reports through GitHub artifact attestations, which private repositories get only on GitHub Enterprise Cloud. Serves [UC-02](USERS.md#uc-02-the-same-verdict-on-every-pull-request) and [UC-03](USERS.md#uc-03-sign-off-from-the-report-alone). Slice R6 of [issue 440](https://github.com/Veridelta/veridelta/issues/440), which closes.
- **Update**: [the roadmap](../docs/roadmap.md) and [the feature map](FEATURES.md) add a faster `count_forgiven_values`, at the maintainer's request. Measured on a million rows from Parquet, counting makes a run 20 to 50% slower, against an estimate of 2 to 7% from a proxy of the comparison step alone. Serves [UC-03](USERS.md#uc-03-sign-off-from-the-report-alone).
- **Update**: [the feature map](FEATURES.md) adds `count_forgiven_values`, which counts per column the values its rules made match, for local runs. It is off by default, because each ruled column keeps a copy of its original values through the join; the configuration guide warns about the memory and the time. A large count tells [P-03](USERS.md#p-03-the-reviewer-who-reads-the-report) which rule to question first. Serves [UC-03](USERS.md#uc-03-sign-off-from-the-report-alone). Slice R5b of [issue 440](https://github.com/Veridelta/veridelta/issues/440).
- **Update**: [the feature map](FEATURES.md) adds the rules applied to the HTML report, and [the roadmap](../docs/roadmap.md) drops them. [P-03](USERS.md#p-03-the-reviewer-who-reads-the-report) needs to see which rules applied, and the report showed none. Each column's rules read as settings and counts, the same for a local and a pushdown run, and a rule's values never leave the comparison. Serves [UC-03](USERS.md#uc-03-sign-off-from-the-report-alone). Slice R5a of [issue 440](https://github.com/Veridelta/veridelta/issues/440).
- **Update**: [the feature map](FEATURES.md) adds mismatch patterns to the HTML report, and [the roadmap](../docs/roadmap.md) drops them. The report names each change that two or more mismatched values share, such as six statuses that changed to `cancelled`, so one systematic cause reads as one line rather than many rows. The patterns are plain grouping of the listed values, so no model decides one. Serves [UC-03](USERS.md#uc-03-sign-off-from-the-report-alone). Slice R4 of [issue 440](https://github.com/Veridelta/veridelta/issues/440).
- **Update**: [the feature map](FEATURES.md) describes the HTML report as it now opens: the verdict in words, how many rows differ, and then each mismatched value with its difference, filtered by column and key. [The roadmap](../docs/roadmap.md) drops that item. A reviewer finds a systematic error, such as four amounts that each rose by 1.00, without scanning a match flag per column. Serves [UC-03](USERS.md#uc-03-sign-off-from-the-report-alone). Slices R2 and R3 of [issue 440](https://github.com/Veridelta/veridelta/issues/440).
- **Update**: [the feature map](FEATURES.md) adds the run record, and [the roadmap](../docs/roadmap.md) drops it. `veridelta run` records hashes of the configuration and the baseline, the commit, and the CI run, in `run --json`, the HTML report, and the pull request comment, and [a decision record](../decisions/git-and-github-are-the-ledger.md) says why git and GitHub stay the ledger. A path stays as given and no user name is kept, so the record names nothing about the person who ran it. Serves [UC-03](USERS.md#uc-03-sign-off-from-the-report-alone) and [UC-02](USERS.md#uc-02-the-same-verdict-on-every-pull-request). Slice R1 of [issue 440](https://github.com/Veridelta/veridelta/issues/440).
- **Update**: [the feature map](FEATURES.md) and [the roadmap](../docs/roadmap.md) add a run record and a report built for sign-off. A reviewer cannot tell from today's report which configuration, baseline, or commit produced it, and finds a mismatch only by scanning a match flag per column. Git and GitHub stay the record of who declared a rule and who approved a run, and the run record's hashes tie a verdict to them. Serves [UC-03](USERS.md#uc-03-sign-off-from-the-report-alone) and [UC-02](USERS.md#uc-02-the-same-verdict-on-every-pull-request). Slice R0 of [issue 440](https://github.com/Veridelta/veridelta/issues/440).
