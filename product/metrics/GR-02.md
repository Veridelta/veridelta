# GR-02: Wrong verdicts open at a release

- **Name.** Wrong verdicts open at a release.
- **The promise it proves.** [UC-02](../USERS.md#uc-02-the-same-verdict-on-every-pull-request) and [UC-03](../USERS.md#uc-03-sign-off-from-the-report-alone): a verdict in CI, or a report a reviewer signs off on, is never known to be wrong at the time it is read.
- **Definition and formula.** The count of open issues labeled `bug` that report a false match or a false mismatch, read on the day a release pull request is opened.
- **Unit and window.** Issues, per release.
- **How it is measured.** List the open bugs and read each title:

  ```bash
  gh issue list --label bug --state open --json number,title
  ```

- **Current value.** Measured 2026-10-06, for 0.14.0: 0. The two open issues on that date, a dependency note and a test run, are not bugs.
- **Target, and the reasoning.** 0 at every release. The maintainer's constraint is that Veridelta can never be riddled with bugs. A known wrong verdict ships only as a documented difference in `docs/pushdown.md`, with a test that pins it, and then it is not a bug.
- **What gaming it looks like, and the guardrail against it.** Not labeling a report `bug`, or closing it as not planned. The bug report form applies the label, and an issue closed without a fix shows in [DR-03](DR-03.md).
- **What decision changes when it moves.** Above 0, no release until the fix is in, as a patch.
