# DR-01: Keys written before the first verdict

- **Name.** Keys written before the first verdict.
- **The promise it proves.** [UC-01](../USERS.md#uc-01-a-first-verdict-on-two-files): a first verdict on two files, with nothing to learn first.
- **Definition and formula.** The number of keys in the smallest YAML configuration with which `veridelta run` compares two Parquet files and exits 0 when they match. A nested key counts once: `source.path` is one key, and `source` alone is none.
- **Unit and window.** Keys, per release.
- **How it is measured.** Copy one Parquet file twice, write the configuration with the fewest keys that runs, and count them:

  ```bash
  cp docs/assets/data/sample_taxi_data.parquet /tmp/legacy.parquet
  cp docs/assets/data/sample_taxi_data.parquet /tmp/modern.parquet
  printf 'primary_keys: [id]\nsource:\n  path: /tmp/legacy.parquet\ntarget:\n  path: /tmp/modern.parquet\n' > /tmp/smallest.yaml
  uv run veridelta run -c /tmp/smallest.yaml -q; echo $?
  ```

- **Current value.** Measured 2026-10-06, on the format inference in 0.15.0: 3 keys, `primary_keys`, `source.path`, and `target.path`. On 0.14.0 it was 5, with `source.format` and `target.format`: without them the run read each file as CSV and exited 3, reporting the primary key as missing.
- **Target, and the reasoning.** 3 keys: `primary_keys`, `source.path`, and `target.path`. The file's suffix says what format it is, so asking for it again is a step with no information in it.
- **What gaming it looks like, and the guardrail against it.** Guessing a format and reading the wrong one. An explicit `format` always wins over the suffix, and a suffix Veridelta does not know keeps today's default rather than guessing.
- **What decision changes when it moves.** At 3, the README and the docs home lead with the three-line case, and the recording shows it.
