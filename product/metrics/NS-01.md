# NS-01: Steps to a correct verdict on the quick start

- **Name.** Steps to a correct verdict on the quick start.
- **The promise it proves.** [UC-01](../USERS.md#uc-01-a-first-verdict-on-two-files): a newcomer reaches a correct verdict with nothing to learn first. [UC-04](../USERS.md#uc-04-let-an-agent-run-the-comparison) shares it: an agent runs the same steps for a person.
- **Definition and formula.** The keys in the smallest configuration with which `veridelta run` compares two Parquet files and exits 0 when they match ([DR-01](DR-01.md)), plus the shell lines the README's quick start needs after Python and uv are installed: one to install, one to run. `validate` is a third line a newcomer may skip, so it does not count.
- **Unit and window.** Steps, per release.
- **How it is measured.** Count the keys with [DR-01](DR-01.md)'s recipe, then the shell lines of the README's quick start that are not optional:

  ```bash
  uv add veridelta
  veridelta run -c veridelta.yaml
  ```

- **Current value.** Measured 2026-10-06, on the format inference in 0.15.0: 5, as 3 keys and 2 shell lines. On 0.14.0 it was 7, as 5 keys and 2 shell lines.
- **Target, and the reasoning.** 5, as 3 keys and 2 shell lines, reached when the format followed the file's suffix. Below 5 there is nothing left to remove that a comparison needs: two paths and the keys to match on, an install, and a run. It was reached in 0.15.0. A later revision of this card may measure time instead of steps, from the recording in the README.
- **What gaming it looks like, and the guardrail against it.** Removing a step by guessing: a format read wrong, or keys picked by name. [GR-02](GR-02.md) holds the line, since a guessed step that yields a wrong verdict is a bug, and [GR-01](GR-01.md) holds it across backends.
- **What decision changes when it moves.** At 5, the README and the docs home lead with the three-line case, and the recording shows it. A change that raises it does not merge.
