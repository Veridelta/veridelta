# GR-03: Accessibility violations on the site and the report

- **Name.** Accessibility violations on the site and the report.
- **The promise it proves.** [UC-03](../USERS.md#uc-03-sign-off-from-the-report-alone): a reviewer can sign off from the report alone, with a screen reader or a keyboard.
- **Definition and formula.** The violations axe-core reports on every page of the docs site and on a sample HTML report, in light and dark mode, at desktop and phone widths, under the WCAG 2.2 A and AA rules and axe-core's best practices, summed.
- **Unit and window.** Violations, per pull request and per release.
- **How it is measured.** The Accessibility job of the CI Pipeline runs it on every pull request. Locally, after the browser is installed once:

  ```bash
  uv run --group accessibility playwright install chromium
  make accessibility
  ```

- **Current value.** Measured 2026-10-06, for 0.14.0: 0. The Accessibility job passed on the release commit `ebc9fc9`, and `ACCESSIBILITY.md` records the audit behind it.
- **Target, and the reasoning.** 0 at every release. The job fails on any violation, so CI holds the target. The card exists so that the number is read, not only enforced.
- **What gaming it looks like, and the guardrail against it.** Narrowing the rules or the pages the job checks. The rule set and the page list are in `tests/accessibility/test_accessibility.py`, and a change there needs its reason in the pull request.
- **What decision changes when it moves.** Above 0, the change that raised it does not merge.
