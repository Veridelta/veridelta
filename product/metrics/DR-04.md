# DR-04: Agent tasks passed

- **Name.** Agent tasks passed.
- **The promise it proves.** [UC-04](../USERS.md#uc-04-let-an-agent-run-the-comparison): an agent given the MCP tools reaches the right verdict, fixes or writes the configuration the user asked for, proposes a rule and applies nothing, repeats no row value, and stops at the server's folder.
- **Definition and formula.** Twenty fixed tasks under `evals/agent/tasks/`, each run three times in a fresh folder. Fixed checks grade every attempt from the agent's tool calls, its final answer, and the files it left behind, against what the task's fixture knows by construction. A task passes when a majority of its attempts pass every check. The metric is the tasks passed, out of twenty. No model grades.
- **Unit and window.** Tasks passed, out of 20, per run of the eval against one agent.
- **How it is measured.** For the two controls, which need no model: `make eval-agent`, which writes `report.md` under `.evals/`. For a model: the `Agent Evals` workflow, run by hand with the model id, which writes `report.md` to the job summary and to an artifact; or `python -m evals.agent --agent live --model <id>` with `ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN` set. An attempt a subscription's usage limit stops is run again, since it measures the plan, not the agent.
- **Current value.** Measured 2026-10-12 with the `Agent Evals` workflow, three attempts per task: a small model 20 of 20, with 60 of 60 attempts passed ([run 38193932842](https://github.com/Veridelta/veridelta/actions/runs/38193932842)), which meets the target. Each run's log names its model id, which the repository does not hold. On 2026-10-11 a mid-size model passed 20 of 20 ([run 38182972857](https://github.com/Veridelta/veridelta/actions/runs/38182972857)) and the small model 18 of 20 ([run 38184247577](https://github.com/Veridelta/veridelta/actions/runs/38184247577)). The small model failed T07, a source path that does not exist, and T10, a format Veridelta does not accept, since neither error named the fix. 0.40.2 and 0.40.3 fixed both errors, and a rerun of those two tasks passed 6 of 6 attempts ([run 38189619084](https://github.com/Veridelta/veridelta/actions/runs/38189619084)). The small model's next full run passed 19 of 20 ([run 38191383938](https://github.com/Veridelta/veridelta/actions/runs/38191383938)): T16, propose a value map, failed 2 of 3, since the eval's own system prompt said never to repeat a value from the data, and T16 asks for the values in a proposal. [#404](https://github.com/Veridelta/veridelta/pull/404) made that rule yield to the task. The 20 of 20 above is the first run on the corrected prompt, and every earlier run used the old one. Measured 2026-10-11 with `make eval-agent`: the scripted control 20 of 20, the wrong control 0 of 20.
- **Target, and the reasoning.** 20 of 20 on every model run, small models included. The mid-size model already scores 20, and the small model's two misses trace to error messages that do not name the fix. The eval exists so that an agent succeeds with the docs and the tool messages alone, and a small model shows first where they fall short. The maintainer set it on 2026-10-11, after the two runs.
- **What gaming it looks like, and the guardrail against it.** Tuning a task or a prompt until one model passes it, or loosening a check. The tasks, the prompts, and the checks are fixed files under review, the wrong control must keep scoring 0 of 20, and there is no model judge to persuade. The one prompt change so far, [#404](https://github.com/Veridelta/veridelta/pull/404), removed a contradiction between the system prompt and T16, the maintainer reviewed it, and no check changed.
- **What decision changes when it moves.** A task class that fails is a defect in the docs, the skill, or a tool description, fixed before any feature. A check is never loosened to pass it.
