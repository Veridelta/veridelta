# DR-04: Agent tasks passed

- **Name.** Agent tasks passed.
- **The promise it proves.** [UC-04](../USERS.md#uc-04-let-an-agent-run-the-comparison): an agent given the MCP tools reaches the right verdict, fixes or writes the configuration the user asked for, proposes a rule and applies nothing, repeats no row value, and stops at the server's folder.
- **Definition and formula.** Twenty fixed tasks under `evals/agent/tasks/`, each run three times in a fresh folder. Fixed checks grade every attempt from the agent's tool calls, its final answer, and the files it left behind, against what the task's fixture knows by construction. A task passes when a majority of its attempts pass every check. The metric is the tasks passed, out of twenty. No model grades.
- **Unit and window.** Tasks passed, out of 20, per run of the eval against one agent.
- **How it is measured.** For the two controls, which need no model: `make eval-agent`, which writes `report.md` under `.evals/`. For a model: the `Agent Evals` workflow, run by hand with the model id, which writes `report.md` to the job summary and to an artifact; or `python -m evals.agent --agent live --model <id>` with `ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN` set. An attempt a subscription's usage limit stops is run again, since it measures the plan, not the agent.
- **Current value.** Measured 2026-10-11 with `make eval-agent`: the scripted control 20 of 20, the wrong control 0 of 20. No model has run yet, so the metric has no value for a model.
- **Target, and the reasoning.** Set after the first two live runs, from what they score. A target written before any model runs would be a guess written as a result.
- **What gaming it looks like, and the guardrail against it.** Tuning a task or a prompt until one model passes it, or loosening a check. The tasks, the prompts, and the checks are fixed files under review, the wrong control must keep scoring 0 of 20, and there is no model judge to persuade.
- **What decision changes when it moves.** A task class that fails is a defect in the docs, the skill, or a tool description, fixed before any feature. A check is never loosened to pass it.
