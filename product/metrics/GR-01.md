# GR-01: Backends with the same verdict locally and in pushdown

- **Name.** Backends with the same verdict locally and in pushdown.
- **The promise it proves.** [UC-05](../USERS.md#uc-05-compare-two-tables-where-they-are-stored), and every use case that compares two tables where they are stored. The pushdown guide promises the same verdict in the warehouse as on a laptop.
- **Definition and formula.** The number of pushdown backends whose parity suite passed against the released version, over the nine backends the suite covers: DuckDB, Postgres, SQL Server, BigQuery, Databricks, MotherDuck, Redshift, Snowflake, and Synapse. A backend counts when every case it does not skip passed. A case skips where the backend refuses its rule by name, which the case checks first, or where it carries a `skip_on` marker because the backend cannot store its data.
- **Unit and window.** Backends, out of nine, per release.
- **How it is measured.** DuckDB, Postgres, and SQL Server run on every pull request, in the `test-core`, `test-postgres`, and `test-databases` jobs of `.github/workflows/ci.yml`. The other six run in the Live Warehouses workflow, `.github/workflows/live.yml`, which a maintainer starts by hand. Read the jobs on the release commit, and the latest run of the workflow:

  ```bash
  gh run list --workflow ci.yml --branch main --limit 1 --json conclusion,headSha
  gh run list --workflow live.yml --limit 1 --json conclusion,headSha
  ```

- **Current value.** Measured 2026-10-16, for 0.41.2: 4 of 9. DuckDB, Postgres 16, and SQL Server 2022 passed in the CI Pipeline, and MotherDuck passed the first run of the Live Warehouses workflow, 222 cases with 4 skipped, which read Parquet through the command line on every backend ([run](https://github.com/Veridelta/veridelta/actions/runs/38974225978)). BigQuery, Databricks, Redshift, Snowflake, and Synapse have not run. Measured 2026-10-11, for 0.39.0: 3 of 8. DuckDB, Postgres 16, and SQL Server 2022 passed in the CI Pipeline on the release pull request, and the Live Warehouses workflow has never run. Synapse makes nine backends, at 3 of 9 until the Redshift and Synapse jobs run. Release 0.38.0 counted 3 of 7, and releases up to 0.37.0 counted 2 of 6.
- **Target, and the reasoning.** 9 of 9 before every release, the first step of a release in `CONTRIBUTING.md`. Releases 0.14.0 to 0.37.0 shipped at 2 of 6: on 2026-10-06 the maintainer let releases ship before the first live run, which [issue 111](https://github.com/Veridelta/veridelta/issues/111) tracks.
- **What gaming it looks like, and the guardrail against it.** Marking cases `skip_on` for a backend until it passes. The guardrail to write: the count of `skip_on` markers changes only with its reason in `docs/pushdown.md`, which a test holds.
- **What decision changes when it moves.** A backend that runs and differs blocks the release until its divergence is fixed, or documented in `docs/pushdown.md` with a test that pins it. A backend that has never run blocks nothing until that first run.
