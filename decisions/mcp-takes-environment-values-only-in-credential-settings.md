**Claim:** On `veridelta mcp`, a `${NAME}` may stand only as the whole value of a credential setting, or as a database uri's whole user or whole password, in that setting's shape, and is refused as it is expanded, before any check or reader. A uri user from the environment holds at most 32 characters, since a database can cut a longer one into its error. Every answer is masked, in any case and percent-encoded too, against every whole value the server has expanded since it started, and never against a part of one. Inside a tool call, a connector masks its own secrets only after that mask. Outside the server, `load_config` and `veridelta validate` change in one way: `_parse_source_ref` now reports an unset `${NAME}` that comes before a refused or malformed reference in the same block. So `veridelta validate --allow-missing-env` warns about that name where it printed only the error before.

**Evidence:** Through the MCP client on origin/main, a value came back unmasked in each of these forms: percent-encoded in a path (`%2B`, `%25`), named through a YAML escape (`\x24{KEY}`), cut by PyIceberg's `parse_location` at `#` or `?`, from Polars' cache of object stores in a later call that never named the variable, cut at a scheme's `:` (`sqlite+${KEY}://x.db`) or at a login's `:` in a uri's user, as the head of a whole `DATABASE_URL`, re-sorted by the Azure SDK from a SAS token written as `"?${SAS}"`, and swapped out of the file between the load and the second read that `environment_values` made. A reader option such as `new_columns`, `row_index_name`, or `include_file_paths`, a `query`, and a glob's brackets also carry a value into a column name or a count. Real S3 also wrote a session token it rejected back into its error, XML-escaped, trimmed, or with its letters outside ASCII decoded as another encoding, so a key or a token must keep a shape that every such echo leaves as it is. A real PostgreSQL 16 wrote the first 63 characters of a 94-character uri user into its authentication error. The uri user is the only slot a database cuts: no reader cuts a password, a token, a key, a SAS token, or a login, Snowflake does not cut its `user`, and an access key id, a client id, or a tenant id is short or echoed whole. MySQL keeps 32 characters of a user name, PostgreSQL 63 bytes, Redshift 127 bytes, and SQL Server and Oracle 128, and MySQL before 5.7.8, which kept 16, is out of support. So a uri user of 32 characters or fewer reaches an error whole, where the mask matches it. A reader masks its side's password in its driver's message, and the file can set one as short as `e`. Against a real PostgreSQL 16, that cut an echoed uri user into pieces before the server's mask ran, and two calls gave the whole value. A prototype that refuses at `config._substitute` refused every one of these configurations and accepted the credential forms. `TestEnvironmentReferences` in `tests/unit/test_mcp_server.py` holds a test for each form, a check that every field outside the slot table is refused, a check that the server loads only through `_load_checked` with its hook, a refusal of a 33-character uri user, a check that a one-letter password in the file cannot split an echoed uri user, a check that neither a guessed head of a recorded value nor a JWT that shares a recorded one's header comes back masked, and a corpus of credential values echoed raw, lowercased, and percent-encoded by every engine call, of which no six characters in a row reach any answer of any tool. `TestReferenceHook` in `tests/unit/test_config.py` covers the hook.

**Alternative considered:** Withhold every reader and driver message once any configuration in the process has expanded a variable, with an allowlist of messages and a mark on each setting a message cites. A second alternative masks each piece of a value and its decoded views. A third masks the heads of each value a database keeps when it cuts a user name: first a list of cut lengths, 16, 32, 63, 64, and 128 characters or bytes, then every head of 16 or more, extended over the rest of the value.

**Why rejected:** Withholding makes the server unable to say why any credentialed read failed, even with `--allow-row-values`, and needs 60 to 80 hand-placed marks where one wrong mark leaks. Piece masking still matches patterns: it leaves cuts at other characters and other encodings open, garbles answers across configurations, and lets an agent guess a value piece by piece. A list of cut lengths missed Redshift's cut at 127 bytes, which left the 63 characters past the 64-character head as they were. Masking every head is a prefix oracle: an agent names guessed heads as columns of an unrelated configuration and sees which come back masked, so it learns a token, in any case, about one character per call. It also over-masks, since tokens of one kind share their opening, such as a JWT's `eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.`, an STS token's `IQoJb3JpZ2luX2Vj`, or a SAS token's `sv=20`, so it garbles unrelated data for as long as the server runs. Capping the uri user at 32 characters closes the cut with neither cost.

**How to reverse:** Keep the hook in `_load_checked` in `src/veridelta/mcp_server.py`, since it also records the values the mask hides, and drop the `_check_reference` call in `_record_and_check` and the SQLite `password` check after the load. Then delete the refusal tests in `TestEnvironmentReferences`, and restore the list of values that come back unmasked in `docs/agents.md`. The mask over recorded values keeps its protection. Passing `on_reference=None` instead would leave the recorded set empty, and every answer unmasked. A narrower step adds a `--public-env NAME` flag that skips the slot table for a variable the operator declares holds no secret. To lift the cap on a uri user, drop the `_LONGEST_URI_USER` check in `_shape_needed` and its refusal test. A database that cuts a longer user name then puts the cut head in an answer unmasked, so lift it only with a way to mask a cut name that reveals no prefix and masks no other token, never with head masking.
