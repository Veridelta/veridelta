**Claim:** On `veridelta mcp`, a `${NAME}` in a database `password`, a Snowflake `password`, or a Snowflake `private_key_passphrase` keeps taking any text in UTF-8 of 4 or more characters. The mask keeps matching a value only as written and in its encodings, never with its quotes doubled, its backslashes escaped, as JSON, inside ODBC braces, or cut. That is safe only while no reader writes a password in such a form. So `_load_checked` takes a `${NAME}` in a database `password` only when `connectorx_url` names a reader in `_PASSWORD_READERS`: PostgreSQL and Redshift, MySQL, SQL Server, Oracle, ClickHouse, and Trino. `tests/integration/test_mcp_password_echo.py` and `tests/integration/test_mcp_password_servers.py` pin the claim for each of them, and for Snowflake, whose connector is the only reader of its password and passphrase.

**Evidence:** Through the MCP client, `test_mcp_password_servers.py` signed in to a local PostgreSQL 16 under `scram-sha-256`, `md5`, and `password` (clear text) with three wrong passwords of every character class, through `validate_config` with schemas. No answer held a run of 4 characters of the password, or any escaped form of it, and the server log showed 21 failed sign-ins for each method. `test_mcp_password_echo.py` drives fakes of PostgreSQL, MySQL, SQL Server, ClickHouse, Trino over HTTP and HTTPS, and Snowflake, with Oracle and a Snowflake key's passphrase, through `validate_config`, `describe_schema`, and `run_comparison`: 78 answers, none with a piece of the password. The Postgres fake asks for the password in clear text and receives it whole. ConnectorX reports only `password authentication failed for user "u"`, ERR 1045 with the user, `Timed out in bb8`, ClickHouse's own text, `basic auth can not be used with http` or the 401 status, `DPI-1047`, and Snowflake's `390100` text. tokio-postgres leaves the login out of its parse errors, such as `parse error: invalid port number`, and a model error names the setting, never its value. The control in the same file has the fake write the password back in 15 escaped forms: each comes back unmasked and is found, and the raw form comes back as `***`. The evidence has limits. Oracle is probed only up to DPI-1047, since CI has no Oracle Client. Trino and Snowflake are driven by fakes only. The corpus pins the driver versions in the lockfile. Trino's host check refuses a password with `@`, `/`, `?`, `#`, `\`, or a space, which tells an agent whether such a character is in it. ClickHouse sends a password still percent-encoded, and Trino re-encodes part of one, so a password with symbols cannot sign in through them, on `veridelta run` too.

**Alternative considered:** Give every secret slot `_UNRESERVED`'s shape, letters, digits, `.`, `_`, `~`, and `-`, as a uri password has. A second alternative adds each escaped form of a recorded value to `_mask_pattern`: quotes doubled, backslashes escaped, JSON, ODBC braces, and libpq quoting.

**Why rejected:** The shape refuses common real passwords and passphrases, such as the defaults of RDS and Secrets Manager, Azure SQL's rules, Snowflake's, and any with a letter outside ASCII, to stop an echo that no reader produces. It would also break the remedy for a uri password with other characters, which moves it to the `password` setting. Escaped forms are a list with no source to check it against, they grow the pattern for every value, none of them matches a cut, and the record that the MCP server takes a `${NAME}` only in a credential setting rejects piece masking.

**How to reverse:** To drop the list of readers, remove `_PASSWORD_READERS` and its branch in `_load_checked` in `src/veridelta/mcp_server.py`, the two tests of it in `TestEnvironmentReferences`, and the sentences about it in `docs/agents.md` and the 0.43.0 section of `docs/upgrading.md`. To move to a shape instead, add a branch for the `secret` slot to `_shape_needed` with `_UNRESERVED`, and list the refused passwords in `docs/upgrading.md`.
