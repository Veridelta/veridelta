**Claim:** On `veridelta mcp`, `_shape_needed` refuses a value of 1 to 3 characters in every credential slot, a login, a `uri` user, and a SAS token included. It also refuses a SAS token whose `sig`, decoded, holds fewer than 4 characters. A refused short login in a `${NAME}` gets a hint to write it in the file. `_environment_values` records `_url_login_values` of every variable: each URL login with the host after it, the login with its `@`, its password as written and decoded, and the Basic credential a proxy receives. It reads a value that starts with `//` as a scheme-relative URL, in any variable. It reads a value with neither a scheme nor `//` as a login only in a variable whose name ends in `_proxy`. It never records the user alone. `_cut_url_login` refuses, at start, any variable that holds a URL with an `@` after a `/`, `?`, `#`, or `\`, since a client writes back a piece of such a login that no mask matches. That holds for an endpoint, such as `AWS_ENDPOINT_URL_STS`, as for a proxy. It holds for an `@` in a URL's path or query too, which the server cannot tell from a cut login. This amends [the record on reader credentials](mcp-masks-reader-credentials-from-its-environment.md). A variable still joins `_ENVIRONMENT_SLOTS` only on evidence. A URL login is recorded by its shape, since a login in a URL is a credential wherever it stands, and it never masks a flag.

**Evidence:** In a PostgreSQL 16 probe, a `uri` user `ab` or `sa` came back twice: once from `DatabaseConfig.redacted_uri`, and once from the server's authentication error. With `abcd`, both came back as `***`. Polars 2.1.0, Polars 1.39.3, and deltalake 1.6.6 wrote the login in `AWS_ENDPOINT_URL` back as written, and object_store sent only SigV4 to the store. requests, botocore, google-auth, and the BigQuery client wrote back a proxy URL they could not parse, and botocore wrote a socks proxy as `http://socks5://...`. reqwest sent the decoded login as `Proxy-Authorization: Basic`. urllib3 ends a URL's authority at the first `/`, `?`, `#`, or `\`. With Polars 2.1.0 and botocore 1.43.123, `HTTPS_PROXY=http://proxyuser9:Pr0xyPass9#corp@...` came back as `Failed to parse: 'proxyuser9:Pr0xyPass9' is not a valid host or port`, and `/`, `?`, and `\` did the same. botocore puts `http:` before a proxy that starts with `//`, and requests does the same, so with Polars 2.1.0, `HTTPS_PROXY=//proxyuser9:Pr0xyPass9@...` came back as `Failed to parse: http://proxyuser9:Pr0xyPass9@...`. botocore puts `http://` before a proxy that starts with neither `http:`, `https:`, nor `//`. So with Polars 2.1.0 and 1.39.3, `HTTPS_PROXY=proxyuser9:Pr0x://yPass9@...` came back as `Failed to parse: 'proxyuser9:Pr0x:' is not a valid host or port`. So `_cut_url_login` and `_url_login_values` skip a scheme only where `_SCHEME` matches: a letter, then letters, digits, `+`, `-`, or `.`, as urllib3 reads one. They skip a leading `//` too. They read any other proxy value from its first character. botocore reads an endpoint the same way. With Polars 2.1.0, botocore 1.43.123, and an AWS profile that assumes a role, `AWS_ENDPOINT_URL_STS` or `AWS_ENDPOINT_URL` set to `http://stsuser9:Q7st/sPass9@...` came back as `Port could not be cast to integer value as 'Q7st'`, and a `#` did the same. `AWS_ENDPOINT_URL_STS=//stsuser9:Q7stsPass9@...`, at a port where nothing listens, came back as `Could not connect to the endpoint URL: "//stsuser9:Q7stsPass9@.../"`. With `http://proxyuser9:Pr0x@yP/ass9@...`, botocore masked the login it parsed and wrote back `http://***:***@yP/ass9@...`, the tail of the password. No probed reader wrote the user alone. PyArrow cuts an endpoint at the login's `:`, but only through `s3.endpoint`, which a tool refuses. Real access key ids, client ids, and tenant ids hold 16 to 128 characters. `tests/integration/test_mcp_environment_logins.py` probes the endpoint with Polars and deltalake, and the proxy and the STS endpoint with Polars, scheme-relative ones and a login cut by `#`, by `/`, and by a `://` after a login with no scheme included, with a control that turns the record off. `TestEnvironmentUrlLogins`, `TestEnvironmentReferences`, and `TestEnvironmentCredentials` in `tests/unit/test_mcp_server.py` cover the masking, the refusals, and the hint.

**Alternative considered:** Refuse a login in each endpoint and proxy variable. Other options were a list of endpoint and proxy names to record, masking the user alone, and recording `//login@`. For a cut login, the options were refusing it only in a proxy variable or in a list of endpoint names, and refusing only an `@` before the host, not one in a path. For short logins, the options were a proof that no service echoes one, and masking a login of 1 to 3 characters.

**Why rejected:** Refusing a proxy login breaks corporate proxies that work today, so only a login no client can parse is refused. Masking the piece of a cut login, such as `user:head`, would mask the head of a value, which the masking rules forbid, and could not foresee every cut. A list of names drifts as readers add variables, and repeats `_ENVIRONMENT_ENDPOINTS` from the change that holds endpoints to `--allow-host`, which refuses an `@` at each call. Refusing a cut login only in a proxy variable leaves an endpoint open, which botocore cuts the same way. A list of endpoint names drifts too: `_ENVIRONMENT_ENDPOINTS`, in the change that holds endpoints to `--allow-host`, leaves out `AWS_ENDPOINT_URL_STS`, which botocore reads. A password that holds both `@` and `/` puts its head before the host, so an `@` in a path can be part of a cut login. A URL such as `https://cdn.example/npm/pkg@3` is refused for it, and can be written with `%40`. Masking the user alone hides a word such as `admin` in every answer. Recording `//` hides the mark `without_queries` finds a URL by, which keeps URL queries in answers. The proof fails, since PostgreSQL and `redacted_uri` write the user back. Masking 1 to 3 characters garbles every answer.

**How to reverse:** In `src/veridelta/mcp_server.py`, drop the `_url_login_values` call in `_environment_values`, with `_url_login_values`, `_LOGIN_IN_URL`, `_LOGIN_AT_START`, and `_PROXY_SUFFIX`. Restore the slot tuple before the length check in `_shape_needed`, and remove `_short_signature`, `_TOO_SHORT`, and the hint in `_check_reference`. Drop the `_cut_url_login` check in `_environment_values`, with `_cut_url_login`, `_AUTHORITY_END`, `_URL_START`, and `_SCHEME`. Then delete `TestEnvironmentUrlLogins`, `tests/integration/test_mcp_environment_logins.py`, and the `_no_url_logins` fixture in `tests/unit/conftest.py`.
