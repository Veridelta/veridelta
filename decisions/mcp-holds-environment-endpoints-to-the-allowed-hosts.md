**Claim:** On `veridelta mcp`, whenever a tool opens a side, the server checks the endpoints a reader of that side's store would take from its process environment. These are the variables in `_ENVIRONMENT_ENDPOINTS`, the `endpoint_url` of the AWS profile the environment selects, the Azure emulator switch, and MotherDuck's settings. Each must meet the three rules a `storage_options` endpoint meets. Its host is given with `--allow-host` and written in `_HOST_AND_PORT`'s shape. Nothing follows the host and port but a single `/`. A value with a scheme starts with `https://`, in lowercase, on this machine too. The check runs whether or not the configuration names its own endpoint, which is simpler and only stricter. The server still starts, and the refusal is a `ConfigError` for that call, which names the variable as it is set and never its value. Nothing is recorded or masked, since an endpoint is no credential. Sign-in and metadata endpoints, which receive only the environment's own credentials, and proxies are left to the operator.

**Evidence:** Through the MCP client on origin/main, a side that named only `s3://lake/a.parquet` read from a plain-HTTP store that `AWS_ENDPOINT_URL` named, and signed the request. A profile's `endpoint_url` received the keys a `${NAME}` gave in `storage_options`. `AZURE_AUTHORITY_HOST` received a client secret from the configuration's `${NAME}` in clear. Probes of Polars 1.39.3 and 2.1.0 and deltalake 1.6.6 against a counting store found each variable in `_ENVIRONMENT_ENDPOINTS`, whose docstring names each reader. `AZURE_STORAGE_USE_EMULATOR` replaced even a checked `azure_storage_endpoint`. MotherDuck's extension, with `MOTHERDUCK_HOST` and `MOTHERDUCK_USE_TLS=false`, fetched `http://127.0.0.1/extension_version` for `md:sales`. A BigQuery client built with default credentials sent `POST /bigquery/v2/projects/p/jobs` to `BIGQUERY_EMULATOR_HOST` over HTTP. `GOOGLE_BASE_URL` was read with `skip_signature`, and not with a bearer token. deltalake refused every `hf://` table before any request, so `HF_ENDPOINT` is left out. Behind a proxy, Polars and deltalake sent only `CONNECT host:443` for the side's own host, and PyArrow ignored `HTTPS_PROXY`. `TestEnvironmentEndpoints` in `tests/unit/test_mcp_server.py` holds every variable to each rule on each kind of side, and covers case, scoping, the switch, MotherDuck, and the profile. `tests/integration/test_mcp_environment_endpoints.py` refuses nine real readers with no request at the store, and its controls show three of them reach it with the rule off, on Polars 1.39.3 and 2.x.

**Alternative considered:** Strip the variables from `os.environ` as the server starts, and refuse every side of that store. Other options were to refuse to start with any such variable set, to check the STS, metadata, and managed identity endpoints too, to cover proxies, and to move the masking test's store to HTTPS.

**Why rejected:** Stripping changes the process environment under the thread Polars reads it from, a direct Python call would check nothing, and it refuses allowed HTTPS endpoints, so a sovereign Azure cloud loses its only sign-in route. Refusing to start stops a local-only server over an unrelated shell variable. Checking sign-in and metadata endpoints breaks every EC2, ECS, EKS, and AKS operator for no gain, since those endpoints receive only the environment's own credentials. A proxy changes the route and not the host, as the probes show, and the HTTPS rule closes the one way it reads a request. HTTPS trust for the masking test was shown on Linux only, and that test is about masking. Four gaps stay open. The profile can change between the server's read and Polars' read, which matters only when `AWS_CONFIG_FILE` lies under a root. A variable no probe has found yet is not checked. DNS decides the address behind an allowed name. And deltalake reads an all-lowercase `aws_session_token` or `aws_access_key_id`, which `_name_as_read` does not fold, a masking gap for a separate change.

**How to reverse:** Remove the `_refuse_environment_endpoints` call in `_refuse_hosts` in `src/veridelta/mcp_server.py`, with `_ENVIRONMENT_ENDPOINTS`, `_EMULATOR_SWITCH`, `_store`, and `_profile_endpoint`. Then delete `TestEnvironmentEndpoints`, `tests/integration/test_mcp_environment_endpoints.py`, the endpoint lines in `tests/unit/conftest.py`, and the environment endpoint bullets in `docs/agents.md`.
